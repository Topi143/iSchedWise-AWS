| semesters  ->  subjects                                    | One-to-Many (1:M)      | One semester carries multiple subjects               |
| buildings  ->  rooms                                       | One-to-Many (1:M)      | One building contains many rooms                     |
| faculty  ->  faculty_availability                          | One-to-Many (1:M)      | One faculty member can have many availability time   |
|                                                            |                        | slots                                                |
| users  ->  trusted_devices                                 | One-to-Many (1:M)      | One user can register multiple trusted devices       |
| sections  ->  schedule_snapshots                           | One-to-Many (1:M)      | One section can have many scoped schedule snapshots  |
| users  <->  programs  (via user_programs)                  | Many-to-Many (M:M)     | Dean users can access many programs; programs        |
|                                                            |                        | accessible to many Deans                             |
| faculty  <->  subjects  (via fac_subj_assign.)             | Many-to-Many (M:M)     | A faculty can be assigned many subjects; a subject   |
|                                                            |                        | to many faculty                                      |
| sections+subjects+faculty+rooms -> schedules               | Composite              | Ties one section, one subject, optional faculty,     |
|                                                            |                        | optional room into a weekly slot                     |
| sections+subjects+faculty+rooms -> exam_sched.             | Composite              | Same as schedules but tied to a specific exam date   |
+------------------------------------------------------------+------------------------+------------------------------------------------------+


------------------------------------------------------------------------------------------
  9.3  Cascade Chain: Curriculum Deletion
------------------------------------------------------------------------------------------

  Deleting a single curricula row triggers an automatic cascade that removes the
  entire hierarchy beneath it:

    curricula              (deleted)
    +-- year_levels        (CASCADE)
        +-- semesters      (CASCADE)
            +-- subjects   (CASCADE)
                +-- schedules                    (CASCADE -- via subjects)
                +-- exam_schedules               (CASCADE -- via subjects)
                +-- faculty_subject_assignments  (CASCADE -- via subjects)

  NOTE: sections and schedules are also cascaded via programs -> sections ->
  schedules, independently of the curriculum hierarchy.


------------------------------------------------------------------------------------------
  9.4  Cascade Chain: Program Deletion
------------------------------------------------------------------------------------------

  Deleting a programs row cascades across two separate branches:

    programs
    +-- sections           (CASCADE)
    |   +-- schedules      (CASCADE)
    |   +-- exam_schedules (CASCADE)
    |   +-- schedule_snapshots (SET NULL on section_id; snapshots retained)
    +-- user_programs      (CASCADE -- removes Dean access grants)
    +-- curricula          (RESTRICT -- deletion is blocked if curricula exist)

  WARNING: curricula uses RESTRICT (no explicit ON DELETE), meaning a program
  CANNOT be deleted while it has attached curricula. Delete the curricula first.
