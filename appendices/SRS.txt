
Appendix A
REQUIREMENTS SPECIFICATION















I. INTRODUCTION

1.1 Purpose

The purpose of this document is to present the Software Requirements Specification (SRS) for the implemented system titled 'iSchedWise: A Web-Based Class Management and Examination Scheduling with Decision Support System for Norzagaray College.' This document defines the functional and non-functional requirements of the system based on its current implementation and serves as a reference for developers, project advisers, and stakeholders involved in the use, evaluation, and maintenance of the system.

1.2 Objectives

The objectives of the iSchedWise system are to improve the efficiency, accuracy, and organization of class and examination scheduling at Norzagaray College. Specifically, the system aims to:
• Automate the preparation and management of class schedules and examination schedules.
• Reduce scheduling conflicts involving rooms, faculty members, sections, and time slots.
• Provide an organized platform for managing faculty, departments, programs, curricula, sections, buildings, rooms, and academic settings.
• Support administrators and deans in making better scheduling decisions through conflict detection, recommendations, and decision support features.
• Preserve scheduling records through archive and history functions for monitoring and review.
• Improve access to scheduling information through a web-based system with reporting and export capabilities.

1.3 Scope

In Scope
• Web-based management of class schedules and examination schedules.
• Secure login and role-based access for super administrators, administrators, and deans.
• Faculty management including teaching load limits, subject assignment, and availability-related data.
• Department, program, curriculum, subject, and section management.
• Building and room management with room type and availability status.
• Conflict detection for section, faculty, room, and time schedule overlaps.
• Decision support through recommendation and conflict resolution assistance.
• Archive and history management for supported records and schedule snapshots.
• Generation of reports and export of schedules to Excel and PDF formats.
• Academic settings management for academic year, semester, exam period, and scheduling time ranges.

Out of Scope
• Student enrollment management.
• Learning management functions such as online classes, grading, or attendance tracking.
• Payroll, accounting, and payment-related processes.
• Student self-service scheduling transactions.
• Full dependency on external AI services for core scheduling operations.

1.4 Definitions, Acronyms, and Abbreviations

SRS - Software Requirements Specification
DSS - Decision Support System
Super Admin - Authorized user with full system-wide control including user and system administration
Admin - Authorized user who manages academic scheduling data and operations across the institution
Dean - Authorized user with access limited to assigned academic programs and related records
Faculty - Instructor record used for teaching assignments, workloads, and schedule matching
Curriculum - Structured set of subjects under a specific academic program
Section - Student group or class block to which schedules are assigned
Scheduling Conflict - A situation where rooms, faculty members, sections, or time slots overlap or violate scheduling rules
Archive - A retained historical record or soft-archived item kept for reference and audit purposes

II. Software Requirements Specifications
This section presents the functional and non-functional requirements of the iSchedWise system. These requirements describe what the system must do and the performance and quality standards it must satisfy based on the implemented academic scheduling environment.

2.1 Functional Requirements
2.1.1 User Authentication and Access Control
• The system shall allow authorized users to securely log in to the system.
• The system shall support role-based access for super admin, admin, and dean accounts.
• The system shall restrict access to authorized users only.
• The system shall support password reset and first-login account setup functions.

2.1.2 User and Administrative Management
• The system shall allow authorized admin-level users to manage user accounts and role-based access, with higher-privilege account control reserved for super administrators.
• The system shall support program-based access restriction for dean accounts.
• The system shall record key user activities related to scheduling and record management.

2.1.3 Faculty Management
• The system shall allow authorized users to add, update, archive, and restore faculty records.
• The system shall store faculty department assignment, maximum teaching units, and subject assignment data.
• The system shall support faculty availability-related information for scheduling purposes.

2.1.4 Academic Structure Management
• The system shall allow authorized users to manage departments, programs, curricula, year levels, semesters, subjects, and sections.
• The system shall organize subjects under specific curricula and programs.
• The system shall support section-based schedule assignment.

2.1.5 Building and Room Management
• The system shall allow authorized users to add, update, archive, and manage building records.
• The system shall allow authorized users to manage rooms by building, room number, room type, and availability status.
• The system shall use room records in class and examination schedule assignment.

2.1.6 Class Scheduling
• The system shall create, update, and manage class schedules based on section, subject, faculty, room, day, and time.
• The system shall use academic year and semester settings in schedule management.
• The system shall help prevent conflicting class assignments before schedules are finalized.

2.1.7 Examination Scheduling
• The system shall create, update, and manage examination schedules based on section, subject, faculty, room, examination date, and time.
• The system shall support exam period settings such as prelim, midterm, and final examinations.
• The system shall apply examination scheduling rules including exam time windows and lunch break configuration.

2.1.8 Conflict Detection and Decision Support
• The system shall detect scheduling conflicts involving faculty members, rooms, sections, and overlapping time assignments.
• The system shall provide recommendations or alternative scheduling options to help resolve detected conflicts.
• The system shall support decision-making through built-in scheduling logic and optional AI-assisted explanations.

2.1.9 Archive and History Management
• The system shall allow supported master records to be archived without immediate permanent deletion.
• The system shall retain archived schedule data for historical reference and review.
• The system shall allow authorized users to view archived records and schedule history.

2.1.10 Reporting and Export
• The system shall generate reports related to class schedules, examination schedules, faculty workload, room utilization, and related scheduling summaries.
• The system shall support exporting selected reports and schedules to Excel and PDF formats.
• The system shall present scheduling information in a format suitable for review, printing, and administrative reference.

2.1.11 Academic and Institutional Settings
• The system shall allow authorized users to manage academic year, semester, schedule hours, exam hours, and related scheduling settings.
• The system shall support institution-level display information used in reports and exported documents.

2.2 Non-Functional Requirements
2.2.1 Usability - The system must provide a user-friendly web interface for super administrators, administrators, and deans. The interface must organize scheduling tasks clearly and support desktop and mobile-responsive access through standard web browsers.
2.2.2 Reliability - The system must maintain accurate scheduling data and must consistently detect conflicts based on available records and configured scheduling rules.
2.2.3 Performance - The system should generate schedules, reports, conflict checks, and exports within a reasonable time under normal institutional usage.
2.2.4 Security - The system must protect user accounts and scheduling data through authentication, role-based access control, password management, and secure form submission.
2.2.5 Availability - The system must be accessible through modern web browsers over a networked environment and must continue core scheduling operations even when optional AI services are unavailable.
2.2.6 Maintainability - The system should be structured to support future updates through modular backend services, database-backed configuration, and organized management of academic records.

III. Hardware Requirements Specifications
This section describes the hardware requirements necessary to support the development, deployment, and operation of the implemented system. It specifies the minimum and recommended hardware configurations required to ensure stable system performance for administrators and other authorized users.

The hardware requirements define the physical components needed by developers, system administrators, and end users. These include computing devices, hosting resources, networking capability, and peripheral devices required for system operation and printed schedule output.

3.1 Overview
The hardware requirements define the physical components necessary for the development, deployment, and operation of the system.
• Development Hardware Requirements
• Client/User Hardware Requirements
• Server Hardware Requirements
• Peripheral Devices (if applicable)

3.2 Development Hardware Requirements
The developers require the following hardware:

• Processor: Intel Core i5 / AMD equivalent or higher
• RAM: 8 GB minimum
• Storage: 256 GB minimum
• System Type: 64-bit architecture
• Keyboard and Mouse

3.3 Client/User Hardware Requirements
This subsection specifies the minimum and recommended hardware requirements for authorized users who will access and operate the proposed system. These specifications help ensure efficient use of the scheduling and reporting functions without significant performance degradation.

3.3.1 Minimum Requirements
• Desktop or Laptop Computer
• Processor: Intel i3 or equivalent
• RAM: 4 GB
• Web Browser: Google Chrome, Mozilla Firefox, Microsoft Edge, or equivalent modern browser
• Stable Internet or Local Network Connection

3.3.2 Recommended Requirements
• Processor: Intel Core i5 or higher
• RAM: 8 GB or higher
• Stable broadband or campus network connection
• Updated web browser for best interface and export performance

These specifications help ensure smoother navigation, faster loading, and more reliable access to schedules, reports, and export features.

3.4 Server Hardware Requirements (For Web-Based Systems)
Since the system is web-based, it requires a server capable of hosting the application and database.

• Cloud Server: AWS or equivalent hosting environment
• Application Runtime Support for Python-based web applications
• Database Server: MySQL or compatible MySQL/MariaDB environment
• Stable Internet Connection
• Secure Data Storage and Backup Capability

3.5 Peripheral Devices
The following devices support system operation:

• Keyboard
• Mouse
• Printer (for printed schedules, reports, and exported documents)

IV. OVERALL DESCRIPTION

4.1 Summary
iSchedWise is a web-based class management and examination scheduling system designed for Norzagaray College. The system helps super administrators, administrators, and deans manage academic schedules by organizing academic records, automating scheduling assistance, detecting conflicts, supporting decision-making, generating reports, and preserving schedule history through archive functions.

4.2 User Characteristics
Super Administrators
• Responsible for full system administration, user management, settings, and institutional oversight
• Expected to have working knowledge of academic scheduling processes and system administration

Administrators
• Manage academic records, faculty assignments, room data, class schedules, examination schedules, reports, and exports
• Familiar with registrar, departmental, or academic scheduling workflows

Deans
• Manage and review schedules and related records for assigned academic programs
• Use the system for program-level scheduling coordination and conflict review

The system is designed to be user-friendly so that authorized users with varying levels of technical experience can perform scheduling tasks effectively.

4.3 Use Case Scenarios
Example Scenario:
1. The super admin, admin, or dean logs in to the system.
2. The authorized user reviews or updates academic records such as faculty, sections, programs, rooms, and schedule settings.
3. The user creates or edits a class or examination schedule.
4. The system checks for scheduling conflicts and presents available recommendations when needed.
5. The user finalizes the schedule and generates a report or export file for administrative use.

4.4 Operating Environment
Hardware Requirements
• Desktop or laptop computer
• Minimum 8 GB RAM recommended for administrative use

Software Requirements
• Operating System: Windows 10 or later, or Linux-based environment for deployment and development
• Programming Language: Python
• Web Framework: Flask
• Database: MySQL
• IDE: Visual Studio Code or equivalent development environment
• Web Browser: Chrome, Firefox, Edge, or equivalent modern browser
• Cloud Platform: AWS or equivalent web hosting platform
• Stable Internet Connection
